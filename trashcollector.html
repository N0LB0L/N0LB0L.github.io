TrashCollector

Autonomous trash-collection robot: follows a line grid, finds bins by AprilTag, lifts and weighs them with a load-cell arm, and climbs a ramp to dump them.

Role
Solo: all behavior and task logic
Platform
Pololu Romi, provided chassis and base firmware
Language
C++
Sensing
Line sensors · UART camera for AprilTags · load cell · IMU
Output
Servo arm · LCD

The taskFind it, weigh it, dump it

The field is a grid of electrical tape with small 3D-printed baskets marked by AprilTags. The robot has to find a basket, lift it with a servo arm, weigh it with a load cell and show the weight on an LCD, then carry it up a ramp to the dump, empty it, and drive back to the start.

The Romi chassis and its base firmware were provided. I designed and wrote all of the behavior.

State machineOne run, start to finish

I wrote the whole behavior as a state machine in C++. Each state hands off to the next when its sensor condition is met.

  1. Follow lineTrack the tape grid
  2. Find binDetect its AprilTag
  3. ApproachLine up with the bin
  4. LiftServo arm picks it up
  5. WeighLoad cell, shown on LCD
  6. Drive to rampBack on the line grid
  7. ClimbIMU sees pitch change
  8. DumpTurn at the edge, empty bin
  9. ReturnDown the ramp to start

Hardest problemRunning out of flash

The problem

As the behavior grew, with line following, tag detection, the arm, weighing, the LCD and ramp detection, the program outgrew the controller's flash memory.

Why it was hard

Every new state and sensor added code, and the limit was fixed by the hardware, so the whole program had to fit inside it.

The fix

I restructured the code, cut unnecessary variables, and switched to smaller fixed-width types like int16_t wherever the values allowed, until everything fit.

Ramp detectionKnowing where it is by how it tilts

The robot can't see the dump, so it uses its IMU. When pitch changes, it knows it's on the ramp. At the edge it turns around, dumps the basket, and drives back down to the start.
